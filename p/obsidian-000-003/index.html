Obsidian + Quartz + GitHub 完整搭建 & 优化方案（含 SEO、多语言、同步规则）

一、整体架构原理

流程链路

Obsidian 本地写作 → Git 增量同步至 GitHub 仓库 → GitHub Actions 自动构建 → Quartz 生成纯静态站点 → GitHub Pages 免费公网托管

核心软件作用

  1. Obsidian：本地 Markdown 知识库，支持双链、图谱、双向链接，纯本地存储
  2. Quartz：Obsidian 专属静态站生成器，原生兼容 Wiki 双链、图片、公式、目录
  3. GitHub：仓库存储源码 + 笔记，Actions 自动部署，Pages 免费托管

二、前期环境准备

1. 必备软件安装

  • Obsidian：官网直接下载，免费版完全够用
  • Git：默认安装配置即可
  • Node.js：安装 LTS 长期支持版（≥20.x）

2. 环境验证命令 

1
2
3

node -v
npm -v
git --version

3. GitHub 准备

  1. 注册 GitHub 账号
  2. 新建空白公开仓库，不初始化 README、不勾选许可证

五、文件同步核心规则（重点）

1. Git 同步逻辑

  • ✅ 增量同步：仅上传「新增 / 修改 / 删除」的文件
  • ✅ 无改动的旧笔记、框架代码、静态资源，完全不重复上传
  • ✅ 节省流量、同步速度快

2. 两种同步方式

  1. 手动同步
1
2
3

git add .
git commit -m "笔记更新"
git push
  1. 自动同步：安装 Obsidian 插件「Obsidian Git」，设置定时自动提交推送

3. 关键区别

  • 文件上传：增量更新
  • 网站构建：全量重新编译整站

每次推送自动触发全站渲染，保证双链、目录、搜索、图谱正常生效

六、GitHub Pages 自动部署

  1. 仓库 → Settings → Pages

  2. 部署配置：

    • Source：Deploy from a branch
    • 分支：gh-pages（Quartz 自动生成）
    • 目录：(root)

  3. 部署完成后自动生成访问链接：

    https://用户名.github.io/仓库名/

七、Google SEO 全套优化方案

1. 原生 SEO 天然优势

  • 纯静态页面，无数据库，访问速度快，契合谷歌核心 Web 指标
  • 自动生成：sitemap.xml、robots.txt、RSS 订阅
  • 全站 HTTPS、全球 CDN 加速，服务器稳定性拉满
  • Markdown 纯净代码，爬虫抓取效率极高

2. 默认配置短板

  • 缺少页面描述、OG 社交标签、规范化链接
  • 图片无 Alt 注释，丢失图片搜索流量
  • URL 路径冗长，移动端体验一般
  • 被动收录，谷歌抓取周期长

3.4 谷歌收录主动提交

  1. 注册：Google Search Console
  2. 域名 DNS 验证所有权
  3. 提交站点地图：域名/sitemap.xml
  4. 定期检查抓取错误、收录量、关键词排名

4. 进阶性能优化

  • 图片批量压缩，开启图片懒加载
  • 选用 Quartz 极简轻量化主题
  • 关闭无用插件，减少网页渲染阻塞

5. 更高 SEO 替代方案

  1. Hugo+Obsidian：SEO 生态最强，结构化数据、内链体系成熟，长期建站首选
  2. Next.js+MDX：高度自定义，支持 SSG/SSR，适合复杂内容站
  3. Obsidian Publish：零代码付费方案，开箱即用 SEO

八、Quartz 多语言完整实现方案

方案 A：目录分离（SEO 首选・推荐）

适合正式站点、谷歌多地区收录，独立语言路由，配置 hreflang 无流量冲突

  zh/        # 中文内容

方案 B：单文件多语言块（个人笔记用）

  1. 安装 Obsidian 插件：mi18n
  2. 内容写法：
1
2
3
4
5
6
7

:::lang zh-CN
中文内容
:::

:::lang en
English content
:::
  • 优点：单文件维护，无需重复创建文档
  • 缺点：同一 URL 承载多语言，SEO 友好度低

方案 C：网站 UI 界面汉化

  1. 进入目录：quartz/i18n/locales/
  2. 新建 / 修改 zh-CN.json 翻译界面文案
  3. 全局配置默认语言：
1
2
3

configuration: {
  locale: "zh-CN",
}

九、常见问题总结

  1. 本地启动报错：检查 Node 版本、重新执行 npm install
  2. 线上部署失败：查看 GitHub Actions 日志，排查 Markdown 语法错误
  3. 双链不生效：必须使用 [[文件名]] 语法，文件存放于 content 目录
  4. 多语言切换异常：核对目录路由、lang 字段统一规范
